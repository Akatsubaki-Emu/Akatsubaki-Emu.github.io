# Core-only iOS test build (no QEMU runtime)

This manual workflow produces an unsigned iOS arm64 IPA containing the Akatsubaki Emu application and its interpreter/AOT code, but **no QEMU engine, QEMU firmware, or QEMU runtime manifest**.

It exists to validate the iOS app shell and the bounded static x86-64 ELF execution path while the separate QEMU combined-work licensing review remains open. It is not a full-system VM build and does not enable Windows 10, QEMU TCI/JIT, or guest graphics through QEMU.

The workflow extracts the four checked-in Icon Composer archives with `scripts/prepare-app-icons.sh`, then installs XcodeGen and regenerates iSteam.xcodeproj from project.yml before building. This ensures the main/nightly icon sets are present and the device project receives the configured GNU C++17 language standard.

## Run

1. Open GitHub Actions and select **Build Core-Only iOS IPA**.
2. Choose **Run workflow** on main.
3. Wait for the Akatsubaki-Emu-CoreOnly-iOS-* artifact.
4. Download the artifact and install the unsigned IPA using SideStore or another permitted signing workflow.
5. Copy the three ELF guests from the downloaded artifact to the iPad. In the app choose **Import Game / Executable**, select each ELF, and launch it.
6. For the XCHG guest, expect `KENRAN_BUTO_XCHG_OK` and exit status 0. For the runtime guest, expect `Linux`, `x86_64`, `KENRAN_BUTO_RUNTIME_OK` and exit status 0.
7. For the interactive stdin guest, wait for `KENRAN_BUTO_STDIN_READY`, type `hello` in the Console input field and press **Send**. Expect `KENRAN_BUTO_STDIN_ECHO:hello`, `KENRAN_BUTO_STDIN_OK` and exit status 0.

The same Akatsubaki-Emu-CoreOnly-iOS-* artifact includes all three ELF guests, their Python builders, focused tests and SHA-256 manifests alongside the IPA, build information and Xcode build log. The artifact also contains `Akatsubaki-Emu-CoreOnly-iOS.ipa.sha256`, and `build-info.txt` records the IPA digest. The XCHG guest prints `KENRAN_BUTO_XCHG_OK`; the uname guest prints `Linux`, `x86_64` and `KENRAN_BUTO_RUNTIME_OK`; the interactive stdin guest blocks in `read(0)`, echoes a line from the Console input field and exits with status `0`. The Ubuntu repository-validation tests execute the ELF builders on x86-64 Linux and verify the generated bytes. The Apple Silicon workflow passes the generated guests to the Swift static-ELF harness, which executes them through the x86-64 interpreter and, in the AOT workflow, exercises native AOT blocks with interpreter side exits.

The diagnostic guest exercises 32-bit accumulator `XCHG EAX,ECX`; 64-bit accumulator `XCHG RAX,R9`; 32-bit register-only ModRM `XCHG R8D,R9D`; 64-bit register-only ModRM `XCHG R10,R11`; MOV immediate; CMP/JNE interpreter-fallback checks; RIP-relative LEA; and Linux `write`/`exit` syscalls. It is a diagnostic program, not a Linux distribution.

## Limits

- The IPA is unsigned. SideStore signing is still required.
- The QEMU runtime is intentionally absent; full-system guest boot is unavailable in this build.
- The ELF interpreter is a bounded diagnostic bring-up path, not a complete Linux ABI. Dynamic ELF dependencies, PT_INTERP, PT_TLS, broad syscalls, and general userspace compatibility remain incomplete.
- This workflow does not publish a GitHub Release or create a tag. The artifact is retained for seven days.
- The separate GPL compatibility gate remains in force for any IPA or runtime that bundles QEMU.


## Additional end-to-end runtime smoke guest

The build now includes a second static guest, hybrid_runtime_smoke.elf. It calls Linux syscall 63 (uname) into a separate writable PT_LOAD segment, writes the virtual sysname and machine fields to stdout, writes KENRAN_BUTO_RUNTIME_OK, and exits with status 0.

Expected console output includes Linux, x86_64, KENRAN_BUTO_RUNTIME_OK, and guest exit status 0.

This guest checks separate RX and RW mappings, the zero-filled data segment, guest-memory write/read permissions, syscall dispatch, stdout and process-exit propagation in one no-JIT interpreter run. The XCHG guest remains the focused instruction/ALU smoke test.

On a physical iPad, import all three ELF files from the core-only IPA's smoke-kit artifact through Import Game / Executable. Launch the XCHG and runtime guests and verify their markers; launch the stdin guest, wait for READY, enter hello in the Console input field, press Send, and verify the echo/completion markers and exit status. Host execution of the Python-generated ELF is not a substitute for this device test.


## GitLab validation artifact

The GitLab main-branch API/web validation pipeline also builds and runs both static guests and retains them as job artifacts for seven days. The job is deliberately manual/API-triggered; if GitLab reports shared-runner quota exhaustion, no tests have run and the pipeline must be retried after quota is restored.


## Native GuestMachine integration regression

The core-only iOS workflow now runs both the runtime and interactive stdin smoke guests through the application's actual GuestMachine, ELF64Loader, LinuxProcessStackBuilder, X86_64Interpreter and C-backed GuestMemory implementation. It checks uname-written guest memory, captured stdout, exit status 0, a second launch after CPU reset, queued read(0) input/echo, and guest-page cleanup after stop.

This closes the previous test-double-only gap for the execution engine. It still does not replace installation and execution on a physical iPad.


## Interactive guest stdin smoke test

The third guest, hybrid_stdin_smoke.elf, writes KENRAN_BUTO_STDIN_READY and blocks in Linux read(0, ...). The Console input field sends a newline-terminated line into the guest's bounded stdin queue. Type hello and press Send; the guest echoes KENRAN_BUTO_STDIN_ECHO:hello, writes KENRAN_BUTO_STDIN_OK and exits with status 0.

The Swift interpreter test prequeues input and verifies the bytes in guest stack memory. The native GuestMachine regression also executes the guest with queued input, verifies the echo and exit, then checks that guest pages are released. The existing Linux syscall tests cover the blocking read/wake-up behavior. This remains a host test until repeated on a physical iPad.
